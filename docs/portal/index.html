Pilares Fundamentais da Plataforma

Construído para suportar operações de provedores regionais a grandes operadoras com máxima resiliência e conformidade regulatória.

API-First & Design-First

Nenhuma linha de código de controller ou DTO é escrita antes do contrato OpenAPI ser formalmente especificado, validado via Redocly CLI e versionado. As interfaces Spring Boot e clientes TypeScript são gerados automaticamente.

OpenAPI 3.0.3 Orval Client Spring Codegen MapStruct

Blindagem Patrimonial & Regimes

Segregação jurídica, societária e operacional rigorosa entre a Operadora de Telecom (SCM) e a Prestadora de SVA (Serviço de Valor Adicionado). Suporte nativo a transições agendadas de regime tributário (Simples, Presumido, Real).

Segregação SCM/SVA Transições Fiscais Auditoria Imutável

Fiscal & NFCom Modelo 62

Emissão digital, autorização SEFAZ e cancelamento de Nota Fiscal de Serviços de Comunicação (NFCom Modelo 62). Geração de lotes compactados no padrão Convênio ICMS 115/03 e upload seguro de certificados digitais A1.

NFCom Mod. 62 Convênio ICMS 115 Certificado A1 SEFAZ WebServices

RADIUS & Automação de Redes

Sincronização em tempo real com tabelas FreeRADIUS (radcheck, radreply, radacct). Desconexão forçada via CoA/PoD (RFC 3576), pools de IPv4/IPv6, CGNAT e provisionamento automático de velocidades e profiles de banda.

FreeRADIUS 3.x MikroTik RouterOS CoA / PoD CGNAT & IPAM

XinguBit Pay & Cobrança Híbrida

Gateway financeiro integrado com geração instantânea de PIX Dinâmico com QR Code copia-e-cola e Webhooks de conciliação imediata, boletos bancários com linha digitável e régua de cobrança automatizada (SMS/WhatsApp/E-mail).

PIX Dinâmico Boletos Bancários Conciliação Automática Régua de Notificações

Event-Driven Architecture & Outbox

Processamento desacoplado de eventos operacionais e financeiros usando o padrão Transactional Outbox. Garante entrega at-least-once de mensagens sem perda de dados mesmo em instabilidades de rede ou servidores externos.

Transactional Outbox Spring ApplicationEvents Webhooks Externos

Como Rodar o Ambiente Localmente

Ambiente 100% conteinerizado pronto para desenvolvimento com um único comando.

# 1. Clonar o repositório git clone https://github.com/RuyXingubit/ispERP.git cd ispERP # 2. Subir todos os containers (Backend, Frontend, PostgreSQL, FreeRADIUS) docker compose up -d --build # 3. Acessar a aplicação # - Frontend: http://localhost:3000 # - Backend API: http://localhost:8080/api # - Docs OpenAPI Local: http://localhost:8085
